# Canonical NMS data contract

## Scope

This contract defines the boundary between changing upstream source files and
the Atlas-AI application model. It has three layers:

1. **Source layer:** exact upstream records and file hashes.
2. **Canonical layer:** stable, typed entities, localization, recipes, and
   assets used across app features.
3. **Feature layer:** lossless JSONB records that can later be projected into
   typed feature tables when product queries are known.

All IDs are case-sensitive source identifiers unless explicitly stated.

## Global rules

- The source Git commit SHA is required on every canonical and feature row.
- ID-keyed JSON object keys are authoritative even when a payload contains a
  differently named ID field.
- Empty source strings become SQL `NULL` in typed columns but remain unchanged
  inside lossless JSONB payloads.
- Numeric strings become `numeric`; integer-only amounts may still be stored as
  `numeric` because upstream values are not guaranteed to remain integral.
- `"true"` and `"false"` become booleans in typed projections.
- Unknown payload fields remain in `attributes` or `payload`; they are never
  silently discarded.
- Recipe ingredient order is significant and is stored as a zero-based
  position.
- Source images are metadata until an approved asset sync records a successful
  Storage upload.

## Private source contract

### `nms_private.import_runs`

One row per attempted source assimilation.

| Column | Type | Rule |
|---|---|---|
| `id` | UUID | Database-generated primary key |
| `source_repository` | text | Required canonical repository URL |
| `source_commit_sha` | text | Exactly 40 lowercase hex characters |
| `source_committed_at` | timestamptz | Nullable if unavailable |
| `status` | text | `staged`, `validated`, `active`, `failed`, or `superseded` |
| `manifest` | jsonb | Input/output hashes, counts, and validation summary |
| timestamps | timestamptz | Start, finish, and activation audit fields |

Only one import may have status `active`.

### `nms_private.source_records`

Lossless record-level staging.

| Column | Type | Rule |
|---|---|---|
| `import_run_id` | UUID | References the import run |
| `dataset` | text | Stable snake-case dataset name |
| `external_id` | text | Object key or record ID |
| `source_ordinal` | integer | Preserves array order and duplicates |
| `payload` | jsonb | Exact upstream JSON record |
| `payload_sha256` | text | Hash of canonical compact JSON serialization |

The primary key is `(import_run_id, dataset, external_id, source_ordinal)`.

## Canonical public contract

### `nms_entities`

Canonical products, substances, and technologies.

Identity:

- Primary key: `(entity_type, game_id)`.
- `entity_type`: `product`, `substance`, or `technology`.
- `game_id`: authoritative source key.

Promoted fields:

- Localization identifiers: `name_id`, `name_lower_id`, `subtitle_id`, and
  `description_id`.
- Current English projections: `name`, `display_name`, `subtitle`, and
  `description`.
- Classification: `category`, `subcategory`, `rarity`, and `legality`.
- Economy: `base_value`.
- Appearance: `icon_source_path`, `icon_storage_path`, `color_r/g/b/a`.
- `attributes`: the complete source entity record for forward compatibility.
- `source_dataset` and `source_commit_sha`: provenance.

The app should display `display_name`, falling back to `name`, then `game_id`.

### `nms_localizations`

Preserves all upstream localization entries, including conflicts.

| Column | Rule |
|---|---|
| `localization_id` | Upstream localization key |
| `locale` | BCP-47-style lowercase code; initial source is `en` |
| `source_ordinal` | Original array position |
| `value` | Exact localized value |
| `is_preferred` | Exactly one true row per `(localization_id, locale)` |

The committed source array's last occurrence is initially preferred to match
the upstream generators. Conflicts remain queryable and are reported by the
transform manifest.

### `nms_recipes`

One row per crafting/refining/cooking operation.

| Column | Rule |
|---|---|
| `recipe_id` | Deterministic text ID generated by the transformer |
| `recipe_kind` | `crafting`, `refining`, or `cooking` |
| output identity | Composite reference to `nms_entities` |
| `output_amount` | Nullable non-negative numeric |
| `time_seconds` | Nullable non-negative numeric |
| `recipe_type` | Source operation/category label |
| `recipe_name` | Source display label |
| `source_ordinal` | Recipe order within an output record |
| `attributes` | Recipe fields not otherwise promoted |

Deterministic recipe IDs:

```text
crafting:product:<output-id>:0
refining:<output-type>:<output-id>:<source-ordinal>
cooking:product:<output-id>:<source-ordinal>
```

### `nms_recipe_ingredients`

| Column | Rule |
|---|---|
| `recipe_id` | References `nms_recipes` |
| `position` | Zero-based order; part of the primary key |
| ingredient identity | Composite reference to `nms_entities` |
| `amount` | Nullable non-negative numeric |
| `attributes` | Original ingredient payload |

The transform fails validation if the ingredient kind is not `product` or
`substance`. Missing entity references are reported and must be zero or
explicitly reviewed before activation.

### `nms_content_records`

A public, lossless compatibility layer for feature datasets not yet normalized.

| Column | Rule |
|---|---|
| `dataset` | Stable dataset name |
| `external_id` | Source object key |
| `source_ordinal` | Preserves ordering |
| `display_name` | Best available source name for list/search UI |
| `icon_source_path` | Best available source icon reference |
| `payload` | Exact source record |
| `source_commit_sha` | Provenance |

Primary key: `(dataset, external_id, source_ordinal)`.

Initial datasets:

```text
bait
building_parts
corvette_parts
expeditions
fish
fossils
legacy_items
purchaseable_building_blueprints
ship_parts
special_purchases
special_rewards
stories
```

### `nms_assets`

Assets are immutable per source revision.

| Column | Rule |
|---|---|
| `source_commit_sha` | Source revision |
| `source_path` | DDS/PNG reference found in source JSON |
| `upstream_png_path` | Case-resolved PNG path in the upstream Git tree |
| `storage_bucket` | Initially `nms-assets` when enabled |
| `storage_path` | `<commit-sha>/<lowercase-upstream-path>` |
| `mime_type` | Expected `image/png` |
| `content_sha256` | Populated after selective fetch |
| `byte_size` | Populated after selective fetch |
| `status` | `referenced`, `missing`, `approved`, `uploaded`, or `blocked` |
| `referenced_by` | JSON array of dataset names |

Source paths are deduplicated within a revision. Storage objects are not
overwritten: a new source commit creates a new immutable namespace.

## Generated transform files

The transformer writes UTF-8 CSV with a header row and Unix newlines:

| File | Load target |
|---|---|
| `source_records.csv` | `nms_private.source_records` staging |
| `entities.csv` | typed entity staging |
| `localizations.csv` | localization staging |
| `recipes.csv` | recipe staging |
| `recipe_ingredients.csv` | ingredient staging |
| `content_records.csv` | feature-record staging |
| `assets.csv` | asset metadata staging |
| `manifest.json` | import-run manifest and validation evidence |

JSON inside CSV is compact, key-sorted UTF-8 JSON. `payload_sha256` is computed
over that exact encoded representation.

## Compatibility policy

- Additive upstream fields require no database migration because they remain in
  JSONB.
- Promoting a new field requires a reviewed migration and a transformer change.
- Removing or changing a typed field is a breaking contract change.
- Dataset renames require an explicit alias/migration; do not infer them from
  filenames silently.
- The transform manifest version changes whenever generated file semantics
  change.
